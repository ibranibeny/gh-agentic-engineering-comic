The parts of GitHub Actions

  1. ⚡ Eventpush, pull_request, issues, schedule, workflow_dispatch
  2. 📄 Workflowa YAML file in .github/workflows
  3. 🧰 Jobseach runs on a runner: GitHub-hosted or self-hosted
  4. 🔧 Stepsa shell script, or a reusable action from GitHub Marketplace

Maya It starts with an event: a push, a pull request, a new issue, a schedule, or someone pressing "Run workflow".

Maya The event starts a workflow, a YAML file that lives in the .github/workflows folder.

Maya A workflow has jobs. Each job runs on a runner: a machine GitHub hosts for you, or one of your own.

Maya And each job runs its steps: a shell script, or a ready-made action from GitHub Marketplace.

Dewi Do the jobs wait for each other?

Bit Jobs run in parallel by default. Add needs: when one job must wait for another.

Maya Here's the deploy workflow from our workshop starter, trimmed a little.

deploy-pages.yml (simplified)

name: Deploy to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm test
      - run: npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: github-pages
    steps:
      - uses: actions/deploy-pages@v4

Maya On every push to main, or a manual run, it tests and builds the site, then deploys it to GitHub Pages.

Bit See needs: build? No green build, no deploy!

Dewi And permissions asks only for what the jobs need: read the code, write to Pages.

Dewi So GitHub Pages always needs a workflow?

Maya Not always. Pages can publish straight from a branch, or from a workflow like this one. We use the workflow, so the tests run first.

Quiz: Where do GitHub Actions workflow files live?

  1. In the repository's README
  2. In the .github/workflows folder, as YAML files
  3. Only in the repository settings
Show the answer

In the .github/workflows folder, as YAML files. Right. Workflows are code, so they live in the repository and get reviewed like code.

What you learned

  • An event (a push, a pull request, a new issue, a schedule or a manual run) triggers a workflow: a YAML file in .github/workflows.
  • A workflow has jobs that run on runners, hosted by GitHub or by you. Jobs run in parallel unless one needs another; steps run a script or a reusable action.
  • GitHub Pages can publish from a branch, or from a workflow that uploads an artifact and deploys it. The workshop uses the workflow, so tests run first.
