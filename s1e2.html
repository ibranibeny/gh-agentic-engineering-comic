  • 🏷️Title"Add a Careers page to the company profile"
  • 📝DescriptionWhat is needed, and why
  • 🔖LabelsSort it: enhancement, content...
  • 🙋AssigneesWho owns it
  • 🧾Issue forms and templatesEvery request asks the same questions

Maya A clear title, and a description of what you need and why. Lina, that part is yours.

Maya Labels sort it and an assignee owns it, so nothing gets lost in a chat thread.

Lina And forms make every request look the same. I can do that from my tablet!

📍 Developer room

Dewi The issue is filed. So now I code straight on main?

Maya Never straight on main. Branch, commit, then open a pull request.

From issue to production

  1. Issuethe request
  2. Branchyour safe copy
  3. Commitseach step saved
  4. Pull requestpropose the change
  5. Reviewdiscuss and approve
  6. CI checksbuild and test
  7. Mergeinto main
  8. CD deploylive for visitors

Maya A branch is your own safe copy. Each commit saves one step of your work.

Maya A pull request proposes merging that branch. Teammates discuss it, review it and approve it.

Bit Meanwhile, automated checks build and test every push. That's CI, continuous integration!

Maya Write Closes #12 in the description, and issue 12 closes by itself when the pull request merges into the default branch.

Maya After the merge, automation deploys the tested change. That's CD, continuous deployment.

Dewi So the pipeline catches problems before our visitors ever see them!

Maya Exactly. And rules can require approvals and passing checks before anyone can merge.

Dewi But who actually runs all those checks and deployments?

Bit On GitHub? GitHub Actions. That's the next episode!

Quiz: The pull request description says "Closes #12". When does issue 12 close?

  1. As soon as the pull request is opened
  2. When the pull request merges into the default branch
  3. When a reviewer approves the pull request
Show the answer

When the pull request merges into the default branch. Correct! Merge into the default branch, and the issue closes automatically.

What you learned

  • Issues track ideas, tasks, feedback and bugs, with labels, assignees and issue forms that ask every requester the same questions.
  • Work on a branch and open a pull request. Discussion, review and automated checks happen there before anything merges.
  • CI builds and tests every change automatically; CD deploys it once it passes. Closes #12 in a pull request closes issue 12 when it merges into the default branch.
